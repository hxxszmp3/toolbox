# 2026-11-03

## MiniReel 更新至 v0.4.2 并上线

**背景**：每日版本检测自动化跑出「无更新」，但独立核实发现脚本漏报——MiniReel 当天已发布 v0.4.2。
根因是 sync-check.js 第 122 行 `strict-max` 取页面所有三段号最大值，而 MiniReel 页脚版权文本含
`PolyForm Noncommercial License 1.0.0`，`1.0.0` 恒大于 `0.4.x`，导致 state 从建基线起就卡在 1.0.0。

### 做了什么

1. **修检测逻辑**：`scripts/watchlist.json` 的 MiniReel 条目加 `anchor: "v<!-- -->(\\d+\\.\\d+\\.\\d+)"`。
   - 走 `anchor` 分支（在**原始 HTML** 上匹配），`stripNoise` 会删 HTML 注释，所以不能用 versionPattern
   - 页面版本徽章在 HTML 里是 `v<!-- -->0.4.2`（Next.js SSR 注释分隔），/versions 与首页都是**新版在前**
   - 隔离副本三连测：state 1.0.0 → 正确报 0.4.2；state 0.4.2 → 无假阳性；模拟 0.4.3 → 能感知
2. **真 state 修正**：`site:MiniReel` 由 `1.0.0` → `0.4.2`（跑真实脚本自然更新，不手改）
3. **换包**（夸克）：4 个 v0.4.2 包上传到 `工具箱/影视区/红果短剧免广告版/` 的 4 个平台目录，
   旧 v0.4.0 四个包 `move` 到 `影视区/_旧版本存档/旧版本存档/`（沿用 0.3.2 的归档惯例）
4. **改站点**：`data.js` 卡片 version v0.4.0 → v0.4.2；`UPDATES` 顶部加 2026-11-03 的 update 条目
5. **版本戳**：`index.html` 的 `data.js?v=20261101k` → `20261101l`（规律是同日期内字母递增）
6. **提交推送**：`bash tools/push.sh`

### 关键坑

- **上游 macOS 包改结构了**：0.4.0 上游直接给 `MiniReel-0.4.0-macos-universal.zip`（单层，直接含 `minireel.app`）；
  0.4.2 上游给 `release-macos.zip`，**里面又套了一层** `MiniReel-0.4.2-macos-universal.zip`。
  为了跟网盘里 0.4.0 那份保持一致（用户解压一次就得到 app），**上传的是内层包**，不是上游的 release-macos.zip
- **Windows 包 PE 头是 0x014c（32 位）不是 x64**：0.4.0 和 0.4.2 **都是**这样 → 是 NSIS 安装器 stub 固定 32 位，
  实际载荷是 x64，**与旧版一致，非回归**，不用管
- **夸克 CLI 没有 delete 命令**：清理旧包只能用 `move` 移到归档目录
- **`browse` 默认只返回第一页**（约 5 条），要拿全量必须加 `--all`
- **`browse` 不支持 `--stdout-only`**（`search` 才支持），传了直接报 unknown option
- **夸克分享是「活的文件夹分享」**：替换目录里的文件后，分享链接自动指向新文件，**不需要重建分享**。
  但 `share-detail` 的 `size` 字段是缓存的旧值（显示旧包总和），别被它误导——用 `share-search` 查分享内实际文件才准
- 上游下载偶发连接失败（curl exit 7），用 `--retry 3 -C -` 断点续传重试即可
