# 2026-11-05

## 四个工具更新上线（Kazumi / zpod / 飞鼠 / GKD 规则）

**背景**：早间的版本检测自动化报出 3 个更新（Kazumi 2.4.3、GKD 规则 v625、飞鼠 v0.8.3），
人工类目里另挖到 zpod 3.0.14（官网安装包文件名含版本号，但脚本归在「需人工查看」）。
用户指示「把这四个软件更新，并更新网站动态」。

### 做了什么

1. **下载上游包**（全部按上游原名保存，便于网盘里一眼认出版本）
   - Kazumi 2.4.3：windows.msix / macos.dmg / android.apk / ios.ipa / linux ×4（deb + tar.gz 各两架构）= 8 个
   - zpod 3.0.14：windows-setup.exe / macos.dmg / arm64-v8a.apk / .ipa = 4 个（官网直链 dl.zpod.net）
   - 飞鼠 v0.8.3：exe 1.5 GB
   - 体积逐一与上游 API 资产 size 比对通过；Kazumi 8 个包另算 md5 复核
2. **换包（夸克）**：每个平台「上传新包 → 旧包 `move` 到 `<分区>/_旧版本存档/`」
   - 新建存档目录：动漫区 / 音乐区 / 实用软件区 各一个 `_旧版本存档`
   - 换完后 `share-detail` 递归确认分享侧已全部指向新版本（活链接，无需重建分享）
   - 飞鼠旧包 `FlyingMouse-Format-Setup-0.6.1-x64.exe`（上游根本没有这个 release，孤儿包）一并归档
3. **改站点**：`data.js` 卡片 version —— Kazumi v2.3.8→v2.4.3、zpod v3.0.12→v3.0.14（音乐区+影视区两处）、
   飞鼠 v0.7.10→v0.8.3、GKD v605→v625；`UPDATES` 顶部加 4 条 2026-11-05 的 update 条目
4. **版本戳**：`index.html` 的 `data.js?v=20261105c` → `20261105d`
5. **顺手修两个检测盲区**
   - zpod 从 `manual` 改成 `site`，锚点抓首页 `<meta name="zpod-version">` → 以后自动检测
   - `siteVersion()` 拆出 `fetchSiteOnce()` + 3 次重试（间隔 3s）→ 修 zpod/四分贝 首访瞬时失败被误报「检测失败」
6. **提交推送**：`bash tools/push.sh`

### 关键坑位（已写进 MEMORY.md）

- **`browse` 单页最多返回 5 条**，`--page-size` 无效 → 目录项多时改用 `search` 按名字定位
- **`search` 不索引 .ipa**（搜 "ipa" 只返回 .apk）→ .ipa 靠 `browse` 父目录拿
- **`search` 也会瞬时 53000** → 脚本化调用要加重试
- **GitHub release 直链 403** → 改用 `releases/tags/{tag}` 的 `assets[].url` + `Accept: application/octet-stream`
- **`rename` items 格式**：`{schema_version:1, items:[{fid, old_name, new_name}]}`，单批 ≤5 条
- **Kazumi 上游已不提供鸿蒙 hap**（2.3.9 起全部 release 都没有）→ 网盘 `手机-鸿蒙/` 的 2.3.1 hap 保持不动
- **上游资产与网盘结构可能不一致**（上游有 `Kazumi_windows_2.4.3.zip`，网盘只放 .msix）→ 以网盘既有结构为准
- GKD 规则.txt 只有 376 B，是 3 个订阅链接而非规则本体 → 规则走订阅自动更新，换包不用动它
